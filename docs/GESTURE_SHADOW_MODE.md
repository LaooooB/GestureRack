# Gesture Rack — Tiny Classifier Shadow Mode

Shadow mode evaluates a trained tiny landmark classifier against the current production right-hand classifier without giving the learned model any control authority.

## Preconditions

1. Keep the normal Gesture Rack VisionEngine running.
2. Calibrate physical hand roles with `CALIBRATE RIGHT` before collecting or judging results.
3. Train/export a candidate model to `VisionEngine/models/right_gesture_landmark_v1.npz`, or pass another model path explicitly.

## Run

From `VisionEngine/`:

```text
python shadow_monitor.py
```

Useful options:

```text
python shadow_monitor.py --seconds 60
python shadow_monitor.py --model models/right_gesture_landmark_v1.npz
python shadow_monitor.py --output C:\temp\gesture-shadow.jsonl
```

The monitor listens to the same protocol-v2 multicast stream already produced by the production sidecar. It does **not** open another camera and it does **not** modify the stable gesture sent to the rack.

## Per-frame comparison

For every resolved physical-right frame, the monitor records:

- production heuristic gesture and confidence
- tiny-model gesture
- tiny-model confidence and top-two margin
- tiny-model inference time
- agreement/disagreement
- current production stable gesture
- sidecar session ID and sequence
- physical-role configuration source

The output is JSONL so disagreements can be inspected without losing temporal order.

## Session boundaries

A VisionEngine restart creates a new `session_id`. Shadow statistics reset at that boundary and the previous session summary is retained. Do not merge adjacent frames from multiple sessions and call that an independent test split; evaluate complete sessions.

## What the live agreement number means

Agreement with the current heuristic is only a debugging signal. High agreement does not prove the learned model is correct, because both classifiers can be wrong in the same way. Promotion decisions still come from labeled held-out sessions generated by `train_tiny_classifier.py`.

Shadow mode is useful for finding:

- classes where the candidate model behaves differently from production
- unstable model confidence around pose transitions
- real inference cost on the target machine
- recurring disagreements that deserve additional labeled examples

## Promotion rule

The learned model remains non-authoritative until all of the following are true:

1. Session-held-out training report passes the promotion gate.
2. Live shadow inference cost is small enough not to materially increase end-to-end latency.
3. Disagreement logs have been reviewed on real camera sessions.
4. Class-specific failure cases have acceptable recall, especially `None` hard negatives and the directional gestures.

Only after those checks should the model be integrated into the production VisionEngine path. Until then, current heuristic/canned fusion remains the source of control events.
